<Info>
  Softmaple requires Node.js 24.12 or newer, pnpm 11, a Supabase project, and
  PostgreSQL credentials for that project.
</Info>

## Architecture

The monorepo contains a Next.js 16 web app, a single-instance Nitro WebSocket
service, Prisma/Supabase migrations, the Lexical editor, and the EG-walker
collaboration packages.

```text
Browser → apps/web → HMAC WebSocket gateway → apps/collab → Supabase Postgres
             └──────────────────────────────→ Supabase Auth / Data API / Storage
```

Document metadata lives in `public.documents`. Document bodies exist only as
immutable EG-walker event batches; no Markdown or editor JSON shadow column is
stored. Markdown, preview, and LaTeX are derived from the current Lexical state.

## Local setup

```bash
pnpm install
cp apps/web/.env.example apps/web/.env
cp apps/collab/.env.example apps/collab/.env.local
cp packages/db/.env.example packages/db/.env
```

Configure `apps/web/.env`:

```env
NEXT_PUBLIC_SUPABASE_URL="https://PROJECT_REF.supabase.co"
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY="sb_publishable_..."
NEXT_PUBLIC_APP_URL="http://localhost:3000"
COLLAB_BACKEND_ORIGIN="http://localhost:3002"
COLLAB_GATEWAY_HMAC_KEY_ID="local-dev"
COLLAB_GATEWAY_HMAC_SECRET="AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8"
```

Configure the collab service with the same project and HMAC secret:

```env
DATABASE_URL="postgresql://postgres.PROJECT_REF:PASSWORD@POOLER:6543/postgres?pgbouncer=true"
SUPABASE_URL="https://PROJECT_REF.supabase.co"
SUPABASE_PUBLISHABLE_KEY="sb_publishable_..."
COLLAB_GATEWAY_HMAC_KEYS='{"local-dev":"AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8"}'
```

Use a direct connection in `packages/db/.env` for migrations:

```env
DATABASE_URL="postgresql://postgres.PROJECT_REF:PASSWORD@POOLER:6543/postgres?pgbouncer=true"
DIRECT_URL="postgresql://postgres:PASSWORD@DIRECT_HOST:5432/postgres"
```

The checked-in HMAC value is local-only. Preview and production need a unique
32-byte unpadded base64url secret. Never expose it through a `NEXT_PUBLIC_`
variable.

## Database

Prisma migrations are the single schema source of truth.

```bash
pnpm --filter @softmaple/db db:generate
pnpm --filter @softmaple/db db:migrate
pnpm --filter @softmaple/db db:verify:collab-security
pnpm --filter @softmaple/db db:types
```

Commit the regenerated `packages/db/src/database.types.ts` whenever the public
schema or RPC surface changes. The avatars bucket accepts JPEG, PNG, and WebP
up to 2 MB; the web action also rejects images above 2048 × 2048.

## Run and verify

```bash
pnpm dev
pnpm format:check
pnpm --filter @softmaple/web lint
pnpm typecheck
pnpm --filter @softmaple/web test -- --run
pnpm --filter @softmaple/collab test
pnpm turbo run build --filter=@softmaple/web --filter=@softmaple/collab
```

`pnpm dev` starts Web and Collab through Turborepo. Browser WebSockets always
use the web origin at `/collab/document` and `/collab/presence`; the browser
must never receive a direct backend URL.

## Real E2E

Playwright uses dynamic ports, starts both services, and refuses to reuse an
existing server. Core E2E never uses a mock Supabase client or a forged cookie.
It requires a dedicated, non-production Supabase project:

```env
DATABASE_URL="isolated pooled database URL"
DIRECT_URL="isolated direct database URL"
NEXT_PUBLIC_SUPABASE_URL="https://E2E_PROJECT_REF.supabase.co"
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY="isolated publishable key"
SUPABASE_SERVICE_ROLE_KEY="isolated service-role key"
E2E_ALLOW_REMOTE_SEED="true"
E2E_SEED_SECRET="a long random bearer secret"
E2E_SUPABASE_PROJECT_REF="E2E_PROJECT_REF"
SUPABASE_PRODUCTION_PROJECT_REF="PRODUCTION_PROJECT_REF"
```

The seed route returns 404 unless all guards pass. Cleanup deletes only the
exact run-scoped test users, whose cascades remove their workspaces; it never
uses broad truncation.

```bash
pnpm --filter @softmaple/db db:deploy
pnpm --filter @softmaple/web test:e2e
```

The `Isolated Supabase E2E` GitHub environment stores these secrets and requires
approval. The regular Chromium smoke suite needs no production credentials.

## Deployment gates

The v1 collab service must run as exactly one Nitro replica because document
fan-out and Presence rooms are process-local. Do not enable horizontal scaling
until shared pub/sub exists.

Before promotion, verify in a real Preview environment:

- HMAC-protected WebSocket upgrades for document and Presence paths;
- direct unsigned backend rejection and reconnect/repair behavior;
- public read-only access and immediate revocation;
- avatar upload, public delivery, replacement, and removal;
- a single Collab replica is configured.

Playwright's local Upgrade-capable gateway covers signed document and Presence
handshakes through that gateway (not against `next dev` directly), but it is
not a release-equivalent test of the Vercel external WebSocket rewrite, so
Preview validation remains a required release gate.
